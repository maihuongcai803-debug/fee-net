# Exp-034：筛查头坍缩的根因、三个隐藏陷阱，与最终有效的保真筛查结果

> 前序：[[Exp_032_Probe_Matrix_Final_and_v6_Launch|Exp-032]]（v5 60 轮基准）、[[Exp_033_Kaggle_v5_Final_Benchmark|Exp-033]]（v5 终版基准）
> 本文数据全部可复现：`scratch/kaggle_v5_results/`（v5 权重）、`scratch/triage_stage2e.pth`（修复后）、`data/mixed_cohort_train/`（部署匹配训练队列）

## 1. 起点：一个必须撤回的漂亮数字

v3（35 轮，验证循环有 bug）时，混合队列筛查给出 **τ\*=0.96、认证 FNR 0.00%、正常帧旁路 64.66%、1.46× 加速**。这组数字曾被写进论文 Table II。

v5（60 轮，修复验证循环后）重跑：**旁路率 0.00%、加速 1.0×**，即"零漏诊"变成**空洞成立**（网关什么都不放行）。我核查 risk 分布：

| 版本 | 病灶 risk | 正常 risk | 分离度 | 旁路 |
|---|---:|---:|---:|---:|
| v3（bug 选中的早期权重） | 0.9687 | 0.9568 | 0.012 | 64.66% |
| v5（正常收敛） | **0.9998** | **0.9997** | **≈0** | 0% |

**结论：v3 的好数字是 bug 恰好把权重冻结在坍缩前的窄区间（分离度仅 0.012）造成的侥幸，不可复现 → 撤回。**

## 2. 根因一：筛查头在"全阳性"训练集上训练

分流头原本在 Kvasir fold-0 的 680 张**训练帧**上训练，而该集合 **100% 含息肉**。交叉熵没有任何阴性样本，最优解就是"恒定输出病灶风险"→ 网关永不旁路。
**筛查网关无法从没有健康帧的数据里学到特异性。**

## 3. 修复方案：两阶段训练

- **阶段 1**（已完成，v5）：Kvasir fold-0 上训练分割主干 + 分流头（全阳性，分流头必然退化）；
- **阶段 2**（本次新增，`tools/train_triage_head.py`）：**冻结主干，只用含阴性的均衡队列微调分流头**；
- **阶段 3**（`tools/eval_mixed_cohort_gate.py`）：在无泄漏混合队列上 `calib 标定 τ* → certify 单次认证`。

## 4. 过程中踩到的三个陷阱（均已修）

### 陷阱 1：`data/kvasir_triage` 存在**测试帧泄漏**
该队列由 Kvasir-SEG 全库构建：**480 张训练图中有 68 张、120 张验证图中有 24 张源自 150 例独立测试帧**。直接用它微调会让后续认证彻底失效。
→ 修复：按文件名回溯源帧，剔除与 `splits.json["test"]` 相交的样本（412 / 96 张剩余）。

### 陷阱 2：**输入分布不匹配**（病灶尺度）
用 `kvasir_triage` 训练后，分流头在内部验证集分离度仅 **+0.12**（准确率 75%），在混合队列上 τ=0.05 就漏诊 88%。
原因：`kvasir_triage` 的病灶样本是**放大裁剪**（息肉占满画面），而部署时的病灶是**完整帧**（息肉占比小）。分流头学到的是"大而亮的息肉=高风险"。
→ 修复：用同一个 `build_mixed_cohort.py` 以 `--source trainval`（fold-0 训练+验证帧，**绝不含测试帧**）构建**分布匹配**的训练队列：850 完整帧病灶 + 1486 黏膜裁剪正常。

### 陷阱 3（最隐蔽）：`requires_grad=False` **挡不住 BatchNorm 统计量被改写**
阶段 2 只训练分流头（12,740 参数），主干参数 `requires_grad=False`。但只要把共享路径整体置为 `train()` 模式，**stem/layer1 的 BN running mean/var 仍会被更新**，分割特征随之漂移：
- 放开 stem+layer1 训练 → 分割 Dice **81.42 → 1.66**（彻底崩塌）；
- 只训头但误置 `gate.train()` → 分割 Dice **81.42 → 14.06**（同样被毁）。
→ 修复：`gate.eval()` 冻结共享路径，仅 `gate.head.train()`；此时 `requires_grad` 与 BN 统计**双重冻结**，分割输出逐位不变。

## 5. 最终结果（有效、可复现、零泄漏）

配置：阶段 2 仅训分流头（12,740 参数，30 轮，AdamW 1e-3），训练数据 = fold-0 训练+验证帧构建的分布匹配均衡队列；认证数据 = 150 例测试帧构建的混合队列（calib 75 病灶+134 正常 / certify 75 病灶+133 正常）。

| 项 | 数值 |
|---|---|
| **分割 Dice / mIoU / HD95**（150 例测试集） | **81.42 / 73.07 / 36.41**（与 v5 基线**逐位相同**，阶段 2 零代价） |
| 校准阈值 τ\* | 0.59（calib 半，CP 上界 3.92%） |
| **独立认证 FNR** | **0.00%**（Clopper-Pearson 95% 上界 3.92% ≤ 5%） |
| **正常黏膜旁路率** | **99.25%** |
| 整体旁路比例 | 63.5% |
| **实测延迟** | 网关 **2.84 ms** / 全路径 **11.30 ms** / 有效 **5.93 ms** |
| **实测加速** | **1.91×** |

**安全性与有效性同时成立**：在 133 张真正无病灶的黏膜上旁路 99.25%，同时 75 张病灶帧零漏诊，且这一结论来自与标定集严格不相交的认证半。

**必须披露的局限**：
1. "正常"样本是**息肉帧的黏膜裁剪**，不是独立健康筛查帧 → 特异性在真实筛查流上的分布会更复杂；
2. 延迟为本地 RTX 4060 Laptop 实测（Kaggle 基准为双 T4），硬件不同不可直接比较；
3. 阶段 2 的队列来自 fold-0 训练+验证帧，**与 150 例测试帧零重叠**（已程序化校验）。

## 6. 对论文的影响（Exp-033 之后的后续修订）

- Table II 的 64.66% / 1.46× / 6.83 ms **撤回**，替换为本文 §5 的 **99.25% / 1.91× / 5.93 ms**（并注明硬件与队列构造）；
- 论文的筛查叙事由"顺带的功能"升级为**有明确失败模式分析 + 两阶段修复 + 有限样本安全认证**的完整方法学贡献——这比单纯的高旁路率更有说服力；
- 建议在论文中保留 §4 的三个陷阱作为"设计注意事项"，因为它们是复现该类系统时必然踩到的坑。
